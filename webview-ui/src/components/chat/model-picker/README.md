# Profile model picker helpers

Public exports are in [index.ts](index.ts). These helpers do not save settings or replace profile state.

- [`useProfileModelCatalog(apiConfiguration)`](useProfileModelCatalog.ts:33) returns the resolved provider, typed model-ID field, raw catalog (or null), loading/error/unsupported flags, a settings fallback message, and a void retry callback. Requires the application's React Query provider. Friendli discovery overrides its static fallback. Local/compound providers stay settings-only.
- Consumers **must** apply [`filterModels(models, provider, organizationAllowList)`](../../settings/utils/organizationFilters.ts:27) before presenting choices. Also omit deprecated models except the current selection, and omit Bedrock's custom-ARN pseudo-choice unless an ARN is already configured. An empty discovery result is a successful empty catalog; allow opening Settings for manual model IDs.
- [`getReasoningSelection(config, modelInfo)`](reasoning.ts:23) returns supported options, the effective current effort (possibly undefined), and whether reasoning is enabled. Explicit capability arrays are authoritative; required effort cannot be disabled. Unset flags follow defaults, while false disables optional effort. OpenAI-compatible manual controls match Settings and use nested custom-model effort, not a stale top-level effort. Binary/budget models expose no effort choices.
- [`createReasoningPatch(config, effort, modelInfo?)`](reasoning.ts:76) returns a wire patch. Pass model metadata to reject unsupported choices; without it, standard providers validate the effort enum only. Manual OpenAI choices are always checked. Null restores defaults; disable turns reasoning off; none is an enabled wire level where advertised. OpenAI nested patches contain only effort.
- [`createModelPatch(config, id)`](profileModelPatches.ts:16) uses the shared provider field and side effects, adds null clears for the enable flag and OpenAI nested effort, and rejects empty IDs or Bedrock choices requiring new ARN configuration. It does not validate catalog membership: select from the filtered catalog, with the host enforcing the allowlist again.
- Submit either patch through the existing profile-model message with the target profile name, expected provider, and values patch. Do not merge the patch into a whole settings snapshot or optimistically overwrite the profile. The host merges it into current storage.

## OpenAI discovery constraints

[`discoverOpenAiModels()`](openAiModelDiscovery.ts:10) sends one typed host request with a fresh request identifier and accepts only the matching response. Uncorrelated Settings responses and stale responses from another profile or retry are ignored. Abort, completion, transport failure, and the ten-second timeout remove the listener and timer immediately. Requests are independent: no serialization, drain listeners, or session-wide failure flags; retry works without reloading.

The host echoes the identifier only when the request includes one, preserving the existing response shape for legacy Settings clients. Correlated missing-config and unexpected fetch failures return an error promptly. The existing fetcher converts network failures and invalid URLs into an empty model list; an empty list remains a successful empty catalog, not an invented default model.

[`useOpenAiModelCatalog()`](useOpenAiModelCatalog.ts:14) requires an explicit base URL and API key, matching the host discovery gate. Inference's default OpenAI URL and placeholder key are **not** discovery defaults; missing/empty configuration is immediately settings-only without sending a request. Empty catalogs, errors, and timeouts must also retain the Settings fallback for manual model IDs. Headers and credentials remain in effect closures and the host payload, never React Query keys or shared catalog caches. Disabled discovery sends no requests and reports neither loading nor error.
