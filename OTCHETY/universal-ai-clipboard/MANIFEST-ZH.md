## 🌍 问题

### 根本矛盾

现代AI代理将**高达90%的输出流量**浪费在单调地重新生成会话上下文中已经存在的内容上。

每次模型编写命令、代码块或文本片段时——它都会从头开始重新生成，即使同样的内容在一分钟前刚刚创建。模型无法以工具化的方式引用已经存在的内容。

### 问题的全球规模

- 全球每天有数百万AI代理在运行
- 每个代理每次会话执行数十次工具调用
- 每次调用中很大一部分是对现有内容的重新生成
- 这导致了巨大的能源消耗、计算浪费和财务成本

### 为什么现有方案无法解决

| 方案           | 局限                               |
| -------------- | ---------------------------------- |
| **提示缓存**   | 仅适用于静态部分，不适用于动态内容 |
| **语义缓存**   | 按查询含义缓存，无法引用片段       |
| **上下文压缩** | 压缩历史，但不提供引用工具         |
| **RAG**        | 从外部来源检索，不复用内部上下文   |
| **工具链**     | 连接调用，但不允许引用其结果       |

## 💡 解决方案：UNIVERSAL AI CLIPBOARD

### 核心思想

AI代理获得**引用已有上下文内容**的能力，而不是重新生成它。在调用任何接受文本参数（命令、代码、文本）的工具时，代理可以指定：「从这里取这个片段」——而不是从头编写。

### 与现有机制的根本区别

AI中所有现有的引用机制（Citations API、Grounding、ContextCite）都沿着 **「代理 → 用户」** 轴工作——它们向人类展示信息的来源。

Universal AI Clipboard沿着 **「代理 → 代理」** 轴工作——它允许代理本身在其自身的工具调用之间重用内容。这是一个全新的类别。

| 机制                | 轴              | 目的                   |
| ------------------- | --------------- | ---------------------- |
| Anthropic 引用      | 代理 → 用户     | 显示答案来源           |
| OpenAI 引用         | 代理 → 用户     | 显示来源               |
| Google 验证         | 代理 → 用户     | 网页搜索确认           |
| **★ UAC（本发现）** | **代理 → 代理** | **在调用之间重用内容** |

## 🧩 五个核心机制

### 机制 1：🔗 语法剪贴板

模型仅指定一个**锚点元素**——函数名、类名或变量名。系统自动：

1. 在指定源（文件、聊天消息、命令输出）中找到此元素
2. 确定其作为语法单元的精确边界
3. 提取整个单元

**节约：** 几个令牌的引用代替数千个令牌的代码。

---

### 机制 2：📇 锚点对引用

模型仅指定所需片段的**开始**和**结束**（各15-40个字符）。系统使用多阶段搜索自动找到两者之间的所有内容：

1. **精确匹配** — 字面找到片段（约70%的情况）
2. **归一化匹配** — 忽略空格、大小写和标点差异
3. **模糊匹配** — 容忍微小拼写错误（约9%的情况）
4. **词边界扩展** — 确保片段完整性

**节约：** 约10个令牌的引用代替200+。

---

### 机制 3：🧠 消息索引图

在处理聊天历史时，会创建一个单独的索引——每个消息及其内部每一行的精确字符位置映射。模型编写类似 `"记录号:起始行..结束行"` 的短引用，系统通过字符位置提取精确片段。

**关键优势：** 模型永远不会看到索引本身——只看到短引用（约5个令牌），但实现100%提取精度。

---

### 机制 4：🔄 转换管道

复制的片段可以在到达工具之前**即时修改**。可用操作：

- **替换** — 更改片段中的子字符串
- **前置** — 在片段前添加文本
- **包裹** — 将片段放入模板
- **追加** — 在片段后添加文本
- **合并**（用于多个引用）— 用分隔符合并片段

所有操作在单个工具调用中完成。

---

### 机制 5：🔁 跨协议引用

引用标记可以直接嵌入任何工具（包括外部MCP服务器）的文本参数中。系统自动识别这些标记并在调用外部服务器之前替换为真实内容。

**结果：** 所有生态系统组件通过统一的引用机制交换数据，无需更改外部服务器的任何内容。

### 🏖️ 隔离的研究子会话

## 🔬 独特性验证

我通过网页搜索系统（Tavily Search，高级深度）进行了**广泛的深入研究**，涵盖以下主题：

- AI代理在工具调用之间的剪贴板复制粘贴
- AI代理的内容引用机制
- 零令牌复制粘贴技术
- 所有已知的引用API（Anthropic、OpenAI、Google、xAI）
- 工具调用输出的重用和缓存

我研究了数十种现有技术、API机制、开源框架和学术协议。

**目标：** 找到任何解决同一问题的方案——允许AI代理在工具调用之间引用现有内容而不是重新生成它。

**结果：没有发现任何类似的东西。**

| 技术                                  | 为什么不是类似物                       |
| ------------------------------------- | -------------------------------------- |
| **引用API (Anthropic/OpenAI/Google)** | 向用户显示来源，不允许代理重用内容     |
| **缓存**                              | 在请求级别工作，不在内容片段级别       |
| **RAG**                               | 从外部知识库检索，不是从当前会话上下文 |
| **现有AI代理**                        | 有历史记录，但工具调用之间没有引用机制 |
| **人类工具 (UiPath, PowerToys)**      | 为人机交互设计，不为AI代理设计         |

> **Universal AI Clipboard 在全球AI代理系统实践中没有类似物。这是一项开创性的技术，创造了一个新类别。**
