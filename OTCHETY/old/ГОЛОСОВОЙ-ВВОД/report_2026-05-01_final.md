# Итоговый отчет: Реализация голосового модуля RooCode

**Дата**: 2026-05-01
**Статус**: Финальный
**Цель**: Выбор оптимального стека технологий для гибридного голосового модуля (Node.js + Rust) с ограничением веса ядра < 500KB и режимом In-Memory.

---

## 1. Введение: Цели и требования

Проект RooCode требует внедрения голосового управления с соблюдением жестких архитектурных ограничений:

- **Гибридная архитектура**: Node.js (Оркестратор, UI, API) + Rust (Audio Core).
- **In-Memory (Zero-Disk)**: Полный отказ от записи аудиопотока на диск. Обработка происходит в оперативной памяти (`Vec<u8>`, `&[f32]`).
- **Вес ядра**: Строго < 500KB для Rust-компонента.
- **Внешние API**: Использование OpenAI-совместимых API (Groq/Whisper) для STT и TTS.
- **Безопасность**: Гарантия отсутствия следов аудио на диске (критично для приватности).

## 3. Рекомендуемый стек (Лучшая связка)

На основе анализа [`OTCHETY/report_2026-05-01_analysis-existing.md`](OTCHETY/report_2026-05-01_analysis-existing.md), для достижения цели < 500KB рекомендуется следующая связка:

### 3.1. Audio I/O: `cpal` (150KB)

- **Роль**: Захват аудиопотока с микрофона.
- **Почему**: Кроссплатформенность, низкая латентность при `BufferSize::Fixed(256)`, прямая передача данных в коллбэк для обработки.

### 3.2. Noise Suppression: `nnnoiseless` (160KB)

- **Роль**: Очистка аудио от шумов (клавиатура, вентиляторы).
- **Почему**: Вес модели всего 60KB (загружается через `include_bytes!`), нейросеть (GRU) дает отличное качество (9/10), Rust-native.

### 3.3. VAD: TEN VAD (306KB) или RMS-based

- **Вариант А (Качество)**: **TEN VAD**. Если позволяет бюджет памяти (306KB), это лучший выбор для точной детекции начала и конца речи.
- **Вариант Б (Вес)**: **RMS + `vad_prob` от nnnoiseless**. Встроенные методы, не увеличивающие вес бинарника.

### 3.4. Wake Word: `Rustpotter`

- **Роль**: Детекция ключевого слова для активации модуля.
- **Почему**: Open-source, написан на Rust, поддерживает обучение своих моделей (tiny/small/medium), минимальное потребление ресурсов.

**Итоговый вес связки**: `cpal` (150) + `nnnoiseless` (160) + `Rustpotter` (200) ≈ **450-500KB** (впритык к лимиту).

## 4. Сравнение с альтернативами

### 4.1. Почему не WebRTC Audio Processing?

- **Вес**: Полный пакет WebRTC весит **> 1 MB** (включая C++ зависимости), что превышает лимит 500KB в два раза.
- **Сложность**: Требует тяжелого C++ toolchain, избыточен по функциям (AEC, AGC) для задач RooCode.

### 4.2. Почему не Speex?

- **Качество**: Алгоритмы устарели. Качество очистки значительно ниже нейросетевых аналогов (RNNoise), звук остается "роботизированным".
- **Статус**: Проект практически не поддерживается.

### 4.3. Почему не Silero VAD / DeepFilterNet3?

- **Silero VAD**: Требует ONNX Runtime, что добавляет мегабайты к весу ядра ("дохренище").
- **DeepFilterNet3**: Отличное качество (PESQ 4.0), но модель весит 1-2MB, что делает невозможным соблюдение лимита < 500KB.

## 5. Выводы и рекомендации по реализации

### 5.1. Реализация In-Memory через `from_static_bytes`

Ключевым моментом для соблюдения режима Zero-Disk является использование метода `from_static_bytes` из библиотеки `nnnoiseless`. Это позволяет вшить веса нейросети (60KB) прямо в бинарник на этапе компиляции, исключая чтение файлов с диска в рантайме.

```rust
// Пример реализации In-Memory (из report_2026-05-01_context7-research.md)
use nnnoiseless::{DenoiseState, RnnModel};

// Веса модели вшиваются в бинарник статически
static MODEL_WEIGHTS: &[u8] = include_bytes!("../weights.rnn");
let model = RnnModel::from_static_bytes(MODEL_WEIGHTS).expect("Invalid model");
let mut denoise = DenoiseState::from_model(model);

// Обработка кадра (480 сэмплов) происходит в памяти
let vad_prob = denoise.process_frame(&mut output, &input);
```

### 5.2. Итоговая рекомендация

Для реализации голосового модуля RooCode следует использовать связку:

1.  **Захват**: `cpal`
2.  **Шумоподавление + VAD**: `nnnoiseless` (использовать `vad_prob` для детекции речи).
3.  **Wake Word**: `Rustpotter` (модели `tiny` или `small` для экономии места).
4.  **Оркестрация**: Node.js через `napi-rs`.

Этот стек гарантирует укладывание в **500KB**, полную поддержку **In-Memory** и высокое качество распознавания речи за счет нейросетевой очистки.
