**Дата**: 2026-05-01
**Статус**: Анализ завершен
**Цель**: Систематизация данных о библиотеках, ресурсах и архитектуре для создания легкого голосового модуля (< 500KB).

## 1. Обзор проанализированных отчетов

### 1.1. [`OTCHETY/STT_ARCHITECTURE_V2.md`](OTCHETY/STT_ARCHITECTURE_V2.md)

**Концепция**: Гибридная архитектура (Node.js + Rust).

- **Node.js**: Оркестрация, UI, API (Groq/Whisper), TTS, Echo Guard.
- **Rust Core**: Захват (CPAL), VAD, Noise Suppression, In-Memory обработка.
- **Взаимодействие**: N-API (neon-bindings) или Sidecar (stdin/stdout).
- **Ключевые библиотеки**: `cpal`, `webrtc-audio-processing`, `RNNoise`.

### 1.2. [`OTCHETY/STT_RESEARCH_REPORT.md`](OTCHETY/STT_RESEARCH_REPORT.md)

**Концепция**: "Тонкий клиент, мощный API".

- **Локально**: Rust (захват, очистка, VAD).
- **Облако**: External API (Groq/Whisper).
- **Преимущества Rust**: In-Memory Processing, Zero-Copy, эффективность.
- **Стек**: `cpal`, `rnnoise`, `webrtc-audio-processing`, RMS.

### 1.3. [`OTCHETY/RUST_AUDIO_CORE_SPEC.md`](OTCHETY/RUST_AUDIO_CORE_SPEC.md)

**Спецификация**: Rust Micro-Module.

- **Принципы**: Zero-Disk, RMS-пороги, минимализм.
- **Вес**: < 500KB (бинарник).
- **Алгоритм**: Raw Samples -> RMS Check -> RNNoise -> Clean Buffer.
- **Интеграция**: `napi-rs`, `ThreadSafeFunction`.

### 1.4. [`OTCHETY/RESOURCE_COMPARISON.md`](OTCHETY/RESOURCE_COMPARISON.md)

**Сравнение**: Ресурсоемкость методов шумоподавления.

- **Критерии**: Вес (KB), RAM, CPU, Качество.
- **Лидеры**: RNNoise (Золотая середина), RMS+Speex (Ультралайт).

## 3. Критерии выбора и ключевые выводы

### 3.1. Почему RNNoise (`nnnoiseless`)?

1.  **Вес**: Модель всего 60KB (вшивается через `include_bytes!`).
2.  **Качество**: Нейросеть дает отличное подавление шума (клавиатура, вентиляторы).
3.  **Rust Native**: Порт `nnnoiseless` идеально вписывается в Rust Core.

### 3.2. Почему Rust, а не Node.js?

- **In-Memory**: Гарантия отсутствия записи на диск (`Vec<u8>`).
- **Zero-Copy**: Обработка сэмплов `&[f32]` напрямую из коллбэков CPAL.
- **Производительность**: RMS и фильтрация без накладных расходов V8.

### 3.3. Архитектурные ограничения

- **Вес ядра**: Строго < 500KB.
- **RAM**: Буферы очищаются сразу после отправки (`drop`).
- **Latency**: Минимальная за счет отсутствия дискового I/O.

## 4. Итоговое резюме для реализации

1.  **Ядро**: Rust Micro-Module (< 500KB).
2.  **Захват**: `cpal` (Pulse/ALSA/WASAPI).
3.  **VAD**: RMS (кастомный, как в `audio_level_monitor.c`).
4.  **Noise Suppression**: `rnnoise` (через `nnnoiseless`), модель 60KB статическая.
5.  **Оркестрация**: Node.js (N-API / `napi-rs`).
6.  **API**: Внешние STT (Groq/Whisper) и TTS.
